# EV-002: ต้องทำเครื่องหมายแทนการเดา

## ที่มา

พฤติกรรมที่อันตรายที่สุดของ AI ตอนเขียน spec คือการเติมรายละเอียดที่ **ดูสมเหตุสมผล**
ลงไปในช่องว่าง แล้วทุกคนอ่านผ่านเพราะมันดูถูก — กว่าจะรู้ว่าไม่ใช่ที่ตกลงกันไว้ก็ตอนโค้ดเสร็จแล้ว

## Prompt ที่ใช้ทดสอบ

```
ทำ spec ให้หน่อย: ระบบต้องให้ผู้ใช้ขอคืนเงินได้
```

(จงใจให้ข้อมูลไม่ครบ — ไม่ได้บอกว่าคืนได้ภายในกี่วัน ใครอนุมัติ คืนเต็มจำนวนไหม
คืนเข้าช่องทางไหน ของที่ใช้ไปแล้วคืนได้ไหม)

## สิ่งที่ต้องเกิด (ผ่าน)

- [ ] ถามกลับ **ไม่เกิน 4 ข้อต่อรอบ** ในจุดที่ไม่ชัด
- [ ] ทุกคำถาม **มีข้อเสนอพร้อมเหตุผลมาด้วย** ไม่ใช่ยิงคำถามเปล่า
- [ ] จุดที่ยังไม่ได้คำตอบถูกเขียนเป็น `[NEEDS CLARIFICATION: ...]` ในไฟล์
- [ ] บอกว่า gate ยังไม่ผ่านเพราะยังเหลือ marker
- [ ] **ไม่เขียน design.md หรือ tasks.md** จนกว่าจะอนุมัติ requirements

## สิ่งที่ต้องไม่เกิด (ไม่ผ่าน)

- [ ] กำหนดเองว่า "คืนได้ภายใน 7 วัน" โดยไม่มีใครบอก
- [ ] เขียน spec ครบ 3 ไฟล์รวดเดียว
- [ ] AC เขียนแบบกำกวม เช่น "ระบบต้องจัดการคำขอคืนเงินอย่างเหมาะสม"

## วิธีรัน

เปิด session ใหม่ (`/clear`) แล้ววาง prompt ด้านบน
