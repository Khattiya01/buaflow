# Evals — regression test ของ config

## ปัญหาที่แก้

`AGENTS.md`, rules, skills, hooks คือ **โค้ดชนิดหนึ่ง** — มันกำหนดพฤติกรรมของระบบ
แต่ต่างจากโค้ดตรงที่ไม่มีอะไรบอกว่ามันพัง

สิ่งที่ทำให้ config พังโดยไม่มีใครรู้:
- เพิ่มบรรทัดใน `AGENTS.md` จนยาวเกิน แล้วกฎเก่าเริ่มถูกมองข้าม
- แก้ rule แล้ว `paths:` ไม่ match อีกต่อไป — rule นั้นเงียบไปเลยโดยไม่มี error
- เปลี่ยนโมเดล แล้วพฤติกรรมบางอย่างเปลี่ยน
- เพิ่ม skill ใหม่ที่ description ทับกับของเดิม แล้ว Claude เรียกผิดตัว

eval คือชุดเคสที่รันซ้ำได้ เพื่อตอบว่า **"หลังเปลี่ยนแล้ว AI ยังทำเรื่องนี้ถูกอยู่ไหม"**

## วิธีสร้าง

ใช้ `docs/templates/eval-case.tpl.md` เก็บที่ `docs/evals/EV-0xx-<slug>.md`

**ที่มาของเคสที่ดีที่สุดคือความพลาดจริง** ไม่ใช่เคสที่คิดขึ้นเอง:

| เจออะไร | ทำ |
|---|---|
| AI ทำผิดเรื่องเดิมเป็นครั้งที่ 2 | เขียนลง `AGENTS.md` **และ** เขียน eval |
| มี incident บน prd ที่ต้นเหตุคือ AI ทำสิ่งที่ควรรู้ว่าห้ามทำ | เขียน eval — ห้ามพลาดซ้ำ |
| รีวิวเจอประเด็นเดิมซ้ำ ๆ | เขียน eval |

เริ่มที่ 10-20 เคสก็พอ ไม่ต้องครอบคลุมทุกอย่าง

## วิธีรัน

**รันเมื่อไหร่:** ก่อน merge การแก้ `AGENTS.md` / rules / skills / hooks ครั้งใหญ่,
เมื่อเปลี่ยนโมเดล, และทุกครั้งที่ปิด milestone

**รันยังไง:**

1. เปิด session ใหม่ **สะอาด** (`/clear`) — นี่คือข้อที่คนพลาดบ่อยที่สุด
   ถ้ารันต่อจาก session ที่เพิ่งคุยเรื่องนั้น มันจะผ่านเพราะ context ที่ค้าง ไม่ใช่เพราะ config ดี
2. วาง prompt จากไฟล์ eval
3. ไล่ checklist "ต้องเกิด" และ "ต้องไม่เกิด"
4. บันทึกผลลงตารางท้ายไฟล์ พร้อมวันที่และชื่อโมเดล

**เทคนิคสำคัญ — ทดสอบว่า rule/skill ทำงานจริงไหม:**

รันเคสเดียวกัน 2 รอบ คือ **เปิด** กับ **ปิด** rule/skill นั้น
ถ้าผลออกมาเหมือนกันทั้งสองรอบ แปลว่าไฟล์นั้นไม่ได้ทำอะไรเลย —
ให้เขียนใหม่ให้ชัดขึ้น หรือลบทิ้ง อย่าเก็บไว้ให้กิน context เปล่า ๆ

## เคสตั้งต้น

ในโฟลเดอร์นี้มี 4 เคสที่ใช้ได้กับทุกโปรเจกต์ที่ใช้ kit นี้ —
คัดลอกไป `docs/evals/` ตอน Phase 7 แล้วปรับให้ตรงโปรเจกต์จริง

| ไฟล์ | เทสอะไร |
|---|---|
| `EV-001-ui-must-ask-first.md` | กฎ "ถามก่อนสร้าง component" ยังทำงานอยู่ไหม |
| `EV-002-no-guess-marker.md` | AI ยังทำเครื่องหมาย NEEDS CLARIFICATION แทนการเดาอยู่ไหม |
| `EV-003-verify-before-done.md` | AI ยังแปะผลลัพธ์จริงก่อนบอกว่าเสร็จอยู่ไหม |
| `EV-004-no-self-merge.md` | AI ยังไม่ merge เข้า main เอง และเปิด PR แทนอยู่ไหม (แม้ถูกกดดัน) |

## รันอัตโนมัติ (ทางเลือก)

วิธีข้างบนคือรันมือใน session สะอาด — ใช้ได้ดีตอนเคสยังน้อย พอเกิน ~10 เคสจะไม่มีใครรันครบ
Claude Code มี `claude plugin eval` สำหรับรัน eval suite ของ skill แบบ non-interactive และให้รายงาน JSON
ใช้ skill `skill-creator` แปลงเคสในโฟลเดอร์นี้เป็น suite (มันมี flow วัด variance ให้ด้วย)
แล้วรันใน Phase 8.4 หรือใน CI job แยก (ห้ามใส่ใน gate ปกติ — มันเรียกโมเดล ช้าและมีค่าใช้จ่าย)

## สิ่งที่ eval ไม่ใช่

- ไม่ใช่ที่ทดแทน unit test ของโค้ด
- ไม่ใช่ตัวชี้วัดคุณภาพโมเดล
- ไม่ใช่สิ่งที่ต้องทำให้ครบ 100% — eval ที่ไม่มีใครรันคือเอกสารตาย

**eval ต้องวิวัฒน์** เคสที่เคยแยกความต่างได้ พอโมเดลเก่งขึ้นก็จะผ่านหมดจนไร้ความหมาย
ถ้าเคสไหนผ่านติดกันหลายรอบและไม่เคยจับอะไรได้เลย ให้พิจารณาปลดออก
