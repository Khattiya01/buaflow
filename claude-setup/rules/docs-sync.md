# กติกาเอกสาร (โหลดอัตโนมัติเมื่อแตะไฟล์เอกสาร)

## หลักการ

**AI อ่านเอกสารเป็นความจริง** ถ้าเอกสารโกหก AI จะเขียนโค้ดผิดต่อเนื่องเป็นทอด ๆ
เอกสารที่ไม่ตรงกับโค้ดอันตรายกว่าไม่มีเอกสาร

## ห้ามแก้ — ต้องเขียนใหม่แทน

| ไฟล์ | เพราะ |
|---|---|
| `docs/adr/*.md` ที่ `Accepted` แล้ว | ADR คือบันทึกประวัติศาสตร์ — เปลี่ยนใจให้เขียน ADR ใหม่ที่ `supersede` อันเดิม |
| `docs/planning/*.md` | ผลการวางแผนที่แช่แข็งไว้ — การเปลี่ยนแปลงไปอยู่ใน spec หรือ ADR |
| `docs/incidents/*.md` ส่วนที่บันทึกไปแล้ว | เขียนต่อท้ายได้ แก้ของเดิมไม่ได้ |
| `docs/intents/*.md` ที่ `rejected` | เก็บไว้เป็นประวัติว่าเคยตีตกเพราะอะไร |

## ต้องอัปเดตคู่กันเสมอ

| เปลี่ยนอะไร | ต้องอัปเดตอะไรตาม |
|---|---|
| API | `docs/api/openapi.json` + Postman collection |
| พฤติกรรมที่ spec พูดถึง | spec ของ feature นั้น **ก่อน** แก้โค้ด |
| component | `docs/design/components.md` |
| สถานะงาน | `docs/backlog/board.md` + ไฟล์ task + `import.csv` |
| การตัดสินใจเชิงสถาปัตยกรรม | ADR ใหม่ |
| คำสั่ง / โครงโฟลเดอร์ / convention | `AGENTS.md` |
| AI ทำผิดซ้ำครั้งที่ 2 | `AGENTS.md` หมวด "สิ่งที่ AI ในโปรเจกต์นี้เคยทำผิด" |

## เขียนยังไง

- **สั้นและเป็นคำสั่ง** ไม่ใช่เรียงความ
- `AGENTS.md` ยาวไม่เกิน ~200 บรรทัด — ยาวกว่านั้น AI จะเริ่มมองข้ามบางข้อ
  เกณฑ์ตัด: *"ถ้าลบบรรทัดนี้ AI จะทำผิดไหม"* ถ้าไม่ผิด → ตัด
- ขั้นตอนที่ยาวเกิน ~30 บรรทัด → ย้ายไปเป็น skill ไม่ใช่ยัดใน `AGENTS.md`
- กฎที่ผูกกับไฟล์บางกลุ่ม → ย้ายไป `.claude/rules/` พร้อม `paths:`
- กฎที่ห้ามพังเด็ดขาด → ต้องมี hook คู่ด้วย ไม่งั้นถือว่ายังไม่เสร็จ
