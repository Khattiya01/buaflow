## 1. รันของจริงก่อน — ห้ามรีวิวโค้ดที่ยังพัง

```
pnpm verify
```

- ถ้าไม่ผ่าน → **หยุด แก้ก่อน** แล้วค่อยเริ่มรีวิวใหม่
- ถ้าผ่าน → **แปะผลลัพธ์จริงให้ผู้ใช้ดู** ไม่ใช่เขียนว่า "ผ่านแล้ว"

## 2. เทียบกับแผน

อ่าน `docs/plans/<T-xxx>.md` (ถ้ามี) แล้วตอบ 3 ข้อ:

- ทำครบทุกข้อในแผนไหม — ข้อไหนไม่ได้ทำและเพราะอะไร
- **มีอะไรทำเกินแผนไหม** — ถ้ามี ต้องอธิบายได้ว่าทำไมจำเป็น ไม่งั้นคือหลุด scope
- Proof ที่เขียนไว้ในแผน ทำได้ครบไหม — **รันจริงแล้วแปะผล**

ถ้าไม่มี plan.md (งานเล็ก) ให้เทียบกับ acceptance criteria ในไฟล์ task แทน

## 3. ตรวจ Definition of Done

เปิด `docs/standards/definition-of-done.md` หมวดที่ตรงกับประเภทงาน
ไล่ **ทีละข้อ** แล้วรายงานตามจริงว่าข้อไหนผ่าน ข้อไหนไม่ผ่าน
**ห้ามติ๊กข้อที่ยังไม่ได้ตรวจจริง**

## 4. ให้ subagent ตรวจ diff

เรียก subagent `code-reviewer` ตรวจ diff ของ branch นี้
subagent จะอ่าน `REVIEW.md` เป็นนโยบาย และ `docs/constitution.md` เป็นเกณฑ์

เหตุผลที่ต้องใช้ subagent: มันไม่เห็นเหตุผลที่คุณใช้ตอนเขียนโค้ด เลยตัดสินจากผลลัพธ์ล้วน ๆ

## 5. ตรวจเพิ่มตามประเภทงาน

**ถ้าแตะ backend/API:**
- [ ] validate input ครบทุกทางเข้า
- [ ] ตรวจสิทธิ์ที่ server และตรวจ ownership ของ record
- [ ] error ตอบตาม envelope กลาง พร้อม code
- [ ] มี unit test มาพร้อมแล้ว และ coverage ไม่ลดลง
- [ ] อัปเดต OpenAPI + Postman แล้ว
- [ ] ไม่ log ข้อมูลอ่อนไหว
- [ ] ไล่ดู query ที่อาจเป็น N+1 หรือขาด index

**ถ้าแตะ UI:**
- [ ] ไม่มีข้อความ hardcode และมี key ครบ th + en
- [ ] ไม่มีสี/ขนาดดิบ
- [ ] ครบทุกสถานะ loading/empty/error
- [ ] responsive, light/dark, a11y พื้นฐาน
- [ ] ประเมินเรื่อง shared component แล้วและบันทึกใน `docs/design/components.md`
- [ ] สร้าง task `-test` แล้ว

**ถ้าแตะ DB:**
- [ ] migration รันขึ้นได้และมีแผน rollback
- [ ] ถ้าเป็น destructive change ได้ทำแบบ expand/contract หรือยัง
- [ ] อัปเดต seed ถ้าจำเป็น

## 6. ตรวจของที่มักหลุด

- [ ] ไม่มี secret หรือค่า hardcode ที่ควรอยู่ใน env
- [ ] ไม่มี log debug ค้าง
- [ ] ไม่มีไฟล์ที่ไม่ควร commit หลุดเข้ามา
- [ ] commit message ถูกรูปแบบและอ้าง task id

## 7. สรุปให้ผู้ใช้ตัดสินใจ

รายงานเป็น:
- **สิ่งที่ทำไปทั้งหมด** (สรุปจาก diff)
- **หลักฐานว่าใช้ได้จริง** (ผลลัพธ์ที่รันมาจริง ๆ)
- **ผลการตรวจ** ผ่าน/ไม่ผ่านข้อไหน
- **ต้องแก้ก่อน merge** / **ควรแก้** / **ข้อสังเกต** (ไม่เกิน 5 ข้อ)
- **สิ่งที่ควรเปิดเป็น task แยก**

แล้วถามว่าให้แก้เลยไหม หรืออนุมัติเพื่อไป `/done`

## 8. ป้อนกลับเข้า config

ก่อนจบ ถามตัวเอง:
- ประเด็นไหนที่ **เจอเป็นครั้งที่ 2** แล้ว → เสนอผู้ใช้ให้เขียนลง `AGENTS.md` หมวด "สิ่งที่ AI ในโปรเจกต์นี้เคยทำผิด"
- ประเด็นไหนที่เป็นกฎห้ามพังและเจอซ้ำ → เสนอให้ทำเป็น rule ใน `.claude/rules/` หรือ hook
- ประเด็นไหนที่ถ้าหลุดไป prd จะเจ็บ → เสนอให้เขียน eval ใน `docs/evals/`

> **AI ไม่อนุมัติงานตัวเอง** คนเป็นผู้ตัดสินใจเสมอ
