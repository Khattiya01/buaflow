# ทำไมมี subagent แค่ 3 ตัว

แนวปฏิบัติปี 2026 สำหรับ Claude Code สรุปได้ว่า:

> ถ้าเป็น **กฎที่ต้องบังคับ** → ใช้ hook หรือ permission
> ถ้าเป็น **ความรู้/วิธีทำ** → ใส่ใน CLAUDE.md หรือ Skill
> ถ้าเป็น **การแยก context** → ค่อยใช้ subagent

**การเขียน agent ตามตำแหน่งงาน (full-stack / QA / PM / DevOps / architect) ไม่ช่วยอะไรแล้ว**
เพราะ Claude ตัวหลักทำได้ทั้งหมดอยู่แล้ว การแยกเป็น "ตำแหน่ง" มีแต่ทำให้
context กระจัดกระจายและต้องคอยส่งข้อมูลข้ามกันไปมา

subagent คุ้มเมื่อ **งานนั้นต้องอ่านของเยอะแต่ส่งกลับมานิดเดียว** — ซึ่งมี 3 กรณีในโปรเจกต์นี้:

| agent | แยก context เพราะ |
|---|---|
| `code-reviewer` | ต้องอ่าน diff ทั้งก้อนแบบเป็นกลาง โดยไม่ถูก "ความทรงจำว่าเพิ่งเขียนอะไรไป" ครอบงำ |
| `test-writer` | ต้องอ่านโค้ดและเทสเดิมเยอะ แต่ผลลัพธ์คือไฟล์เทสไม่กี่ไฟล์ |
| `legacy-explorer` | โค้ดโปรเจกต์เก่าใหญ่มาก ถ้าอ่านใน context หลักจะบวมจนงานหลักเสียคุณภาพ |

ส่วนงานค้นหาทั่วไปให้ใช้ **Explore** ที่มีมาให้อยู่แล้ว ไม่ต้องเขียนเอง

## ถ้าอยากเพิ่ม agent ทีหลัง
ถามตัวเองก่อนว่า **"งานนี้ทำให้ context หลักบวมโดยไม่จำเป็นไหม"**
- ถ้าใช่ → เขียน subagent
- ถ้าไม่ แต่เป็นวิธีทำที่ต้องอธิบายซ้ำทุกครั้ง → เขียนเป็น **slash command** ใน `.claude/commands/`
- ถ้าเป็นกฎที่ห้ามละเมิด → ใช้ **hook** ใน `.claude/settings.json`
