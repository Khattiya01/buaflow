# ทะเบียนหลักฐาน — <ชื่อโปรเจกต์>

> **เก็บที่ `docs/discovery/evidence-register.md`** — ใช้ก่อนเข้า Intent Compiler เมื่องานเป็นระดับ
> new-product หรือ major-initiative (ดูเกณฑ์ที่ `docs/standards/discovery-and-validation.md`)
> งานเล็ก/งานปกติ **ไม่ต้องมีไฟล์นี้** — ข้ามไปเขียน `/intent` ตรง ๆ ได้เลย
>
> **หลักการ:** ทุก pain point ในทะเบียน pain point (`pain-point-register.tpl.md`) ต้องอ้างกลับมาที่แถวใดแถวหนึ่งในนี้
> ด้วย evidence id — pain point ที่ไม่มีหลักฐานรองรับคือความเห็น ไม่ใช่ปัญหาที่พิสูจน์แล้ว
>
> **ID ขึ้นต้นด้วย `EVD-`** (ไม่ใช่ `EV-`) เพราะ `EV-xxx` ถูกใช้แล้วสำหรับ eval case (`docs/evals/EV-000-*.md`,
> `templates/eval-case.tpl.json`) — คนละเรื่องกัน (eval case เทส config ของ AI, ทะเบียนนี้เก็บหลักฐานของปัญหาธุรกิจ)
> แต่ใช้ prefix เดียวกันจะสับสนและชนกันได้ถ้ามีสคริปต์ไล่ scan id ในอนาคต (ดู DV-002)

## กฎ
- 1 แถว = 1 ชิ้นหลักฐาน (คำพูดผู้ใช้, log, ตัวเลข, ภาพหน้าจอ, incident, ผลสำรวจ)
- **`confidence` ต้องเลือกตามความจริง ไม่ใช่ตามที่อยากให้เป็น** — `assumed` ไม่ใช่ระดับที่ต่ำต้อย
  แค่ต้องบอกตรง ๆ ว่ายังไม่มีอะไรยืนยัน จะได้รู้ว่าตรงไหนของแผนที่เสี่ยงเดาผิด
- หลักฐานเก่าเกิน `coverage` ที่ระบุ (เช่น log ของ role อื่น, ของ feature เก่าที่เปลี่ยนไปแล้ว) → อย่าลบ ใส่ `superseded_by` แทน

## ระดับความเชื่อมั่น (`confidence`)

| ระดับ | ความหมาย |
|---|---|
| `measured` | มีตัวเลขวัดได้จากระบบจริง (log, analytics, query) |
| `observed` | เห็นด้วยตาตรง ๆ (จับตาดู user ใช้งาน, สังเกตหน้างาน) แต่ไม่ได้นับเป็นตัวเลข |
| `reported` | คนอื่นเล่าให้ฟัง (ผู้ใช้, sales, support) ยังไม่ได้ตรวจสอบเอง |
| `assumed` | ยังไม่มีหลักฐาน เป็นสมมติฐานที่ต้องตรวจสอบภายหลัง |
